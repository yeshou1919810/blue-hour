# 蓝调补给站 · 视觉交互原型

一个以帖子和评论区为中心的运动健康 AI 社区。用户发起话题，公开标注身份的 AI 搭子回帖，用户可以在同一讨论中继续追问。

**[直接体验在线网页](https://yeshou1919810.github.io/blue-hour/)** · [GitHub 源码仓库](https://github.com/yeshou1919810/blue-hour)

**[重播蓝色退潮开场](https://yeshou1919810.github.io/blue-hour/?intro=1)**：四层波浪、白底文案与首页依次揭幕，约 4.8 秒。可按 Esc 或点击“跳过”；普通访问每个标签页会话播放一次。配置、视频替换方式与验证命令见 [开场动画说明](docs/intro.md)。

当前版本是 **v0.1 本地交互原型**，用于确定界面与产品体验。没有接入真实模型、识图、RAG、账号系统或外部工具。不要把模拟任务进度当作已经实现的 Agent 能力。

已配置 GitHub Pages 自动部署：将源码推送到 `main` 后，工作流会检查代码并发布 `dist/`。部署配置与更新方法见 [部署说明](docs/deployment.md)。线上版本无需启动本机服务器。

## 第一步：启动并体验

电脑安装 Node.js 20 或以上版本后，在本文件所在目录打开终端：

```powershell
npm run dev
```

打开终端显示的地址：`http://127.0.0.1:4173`。

也可以在 Windows 文件资源管理器中双击 `启动原型.cmd`，或在上一级“竞赛网页”文件夹中双击 `启动网页.cmd`。启动成功会自动打开浏览器。保持终端窗口开启；按 Ctrl+C 停止服务。本阶段不需要安装依赖，也不需要 API 密钥。

注意：在 Codex 聊天中点击代码文件链接，通常只是打开文件查看内容，不会执行启动脚本。网页地址必须在本地服务运行时才能访问。若提示“无法访问 127.0.0.1”，先检查启动窗口是否存在、是否显示“蓝调补给站已启动”。两个启动脚本使用 ASCII 内容和 Windows 换行，避免批处理中文编码导致的命令解析问题。

建议按以下顺序体验：

1. 浏览社区，尝试“运动训练”等分区和顶部搜索。
2. 点击一条帖子，查看 AI 回帖，再点“追问阿燃”。
3. 发送追问，观察右侧任务进度与评论区流式文字；可以停止回复。
4. 发布自己的问题，附上一张图片，体验本地预览与模拟回复。
5. 收藏帖子，进入“我的收藏”；在“我的节奏”完成生活小行动。
6. 用浏览器返回、前进，检查页面切换。

## 第二步：认识文件

为了先专注视觉与交互，这一版使用不依赖框架的 HTML、CSS 和 JavaScript。下一阶段确认设计后，再迁移为 React + TypeScript 的组件化前端，连接队友的接口。原型代码不能直接代表比赛最终的工程质量完成度。

| 文件 | 用途 |
| --- | --- |
| `dist/index.html` | 页面入口和弹窗容器 |
| `dist/styles.css` | 蓝色设计系统、布局、斜切转场、动效 |
| `dist/tide.svg` | 原创月面、水波与透视反射主视觉 |
| `dist/app.js` | 页面渲染、路由、发帖、追问和交互状态 |
| `dist/data.js` | AI 角色、初始演示帖子和生活清单 |
| `dist/mock-agent.js` | 模拟任务事件与流式回复，后续由真实服务替换 |
| `server.mjs` | 只用于本地预览的静态文件服务器，不是业务后端 |
| `docs/backend-contract.md` | 交给后端队友讨论的接口草案 |
| `scripts/qa.mjs` | 本机 Chrome 浏览器回归检查与多尺寸截图 |

运行语法检查：

```powershell
npm run check
```

项目直接提供静态源文件，没有额外的构建步骤或需安装的依赖。

浏览器检查需要 Node.js 22 或更高版本以及默认位置安装的 Windows Chrome。保持预览服务运行，然后在另一个终端执行：

```powershell
node scripts/qa.mjs
```

脚本使用 `.qa/chrome-profile` 独立测试配置，不操作你的日常浏览器数据；结果与截图保存在被 Git 忽略的 `.qa/` 中。检查包含搜索筛选、收藏点赞、发帖和图片预览、追问与停止、浏览历史和持久化，以及 1440、1024、768、390px 下各页面和弹窗的布局、键盘焦点与减少动画偏好。此脚本验证的是本地原型，不代表真实 AI 或后端接口已通过测试。

## 已实现的原型体验

- 社区首页、话题详情、我的收藏、我的动态、我的节奏。
- 分区筛选、关键词搜索、推荐/热门/最新排序、点赞和收藏。
- 发帖弹窗、表单校验、图片类型与大小校验（5 MB）。
- AI 身份标签、指定回复对象、上下文追问、模拟流式回复、取消回复。
- 可见的任务步骤与进行/完成/停止状态，未展示模型内部推理。
- 斜切页面转场、悬停动效、原生弹窗焦点约束、键盘发送、系统减少动画偏好适配。
- 文字内容、点赞、收藏和清单保存在当前浏览器 LocalStorage。

图片使用浏览器临时 URL，只在当前打开的会话中预览，不上传、不持久保存。刷新后附图消失；后续应由真实上传服务负责持久化。当前没有公共社区数据同步，初始作者与帖子均为虚构演示内容。

## 视觉方向

参考《女神异闻录 3 Reload》的蓝色主题、明暗对比、斜切构图与动感排版。角色、图形、标志和页面内容为本项目原创绘制，未使用游戏角色立绘、配乐或截图。参考页面：https://persona.atlus.com/p3r/index.html?lang=en

全宽首屏以超大中文标题、斜切蓝色色块、月面水波 SVG 和英文装饰字建立视觉重心；社区列表使用明亮的阅读面板，详情、收藏、动态、节奏和弹窗沿用相同的编号、细线与蓝白构图。没有新增第三方依赖。

主题变量集中在 `dist/styles.css` 的 `:root` 中，涵盖颜色、间距、字号、切角、阴影和动画时长。常规悬停反馈为 160ms，进入与页面转场为 360ms，并支持 `prefers-reduced-motion`。

桌面使用编号侧边导航；900px 以下将同一导航变为支持 Esc、焦点循环与焦点恢复的抽屉，右栏移到正文下方。600px 以下为单栏，保留完整字号、触摸操作和评论区就近停止回复按钮。页面正常纵向滚动，弹窗支持键盘和内部滚动。

## 健康内容与数据边界

AI 搭子是生活交流角色，不是医生。正式版需要与后端共同设计诊疗问题的边界、风险提示、依据展示和个人数据保护。不得将模型密钥放在浏览器代码或公共仓库中；模型调用与密钥管理由后端完成。
